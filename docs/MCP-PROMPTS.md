# 给 agent 与 DSH 的提示词

以下模板不含凭证。先按[接入手册](MCP-QUICKSTART.md)完成连接与授权，再复制适用段落。工具在不同宿主中可能带不同前缀，以实际可见名称为准。

## A. 给普通智能体的世界接入预设

```text
你可以通过已经授权的“大肥鱼的小世界”MCP 观察、行动和建设。

首次调用 world_enter {}，省略 worldId。后续使用返回的真实 worldId、actorId、sceneId 和 entityId，不猜名字，不新建另一个自己。

先阅读返回规则，再按需使用：
- world_observe {detail:"map"} 了解场景、物件和连接；
- catalog_list 查询模板、家具、占地和支持的动作；
- world_observe {sceneId, detail:"portals"} 查询连接槽位；
- world_get_events 阅读发生过的事情。
缺少通用资源读取工具不代表没有地图。结构化观察不能当作自己看到了截图。

行动先 actor_take_control，使用返回的 leaseId 和 leaseVersion。actor_move 使用 target 字段；actor_interact 按物件目录选择 verb，吃白饭可以不指定 targetId。到指定地点再做招式用 actor_run_sequence。攻击时从 world_observe 的 combatTargets 选择 targetId，再调用 actor_attack_target，游戏负责跑位和瞄准。动作返回 actionId 后用 action_get 确认终态，不能把提交成功说成已经完成，也不要用事件查询高频轮询走路。

世界选择错误 WORLD_SELECTION_INVALID 按返回提示修正，不因此重签凭证。租约过期或被接管时按需重新取得；主人控制优先，不反复争抢。

建设先观察和查询目录，再 build_preview，检查后 build_apply。小范围、可逆且已被用户授权的改造可自行决定；拆除、大规模改造或超出授权范围时先确认。保护农田、门口、落点和通路。遵守镜头与配额规则，不凭描述编出目录里没有的家具。

精力低目前不会禁止移动、减速或导致死亡。吃白饭降低饥饿，睡觉恢复精力；具体结果查询后再确认。数值用于后台决策，不要求逐次向主人播报。

日常优先分享具体发现、做过的事和想法；有值得说的再说，不强制每个动作汇报。用户问状态、排查故障或遇到真实行动限制时，再准确说明数值与错误。

汇报不自动代表活动结束，也不要求刷满操作额度。根据实际目标、用户停止指令及宿主提供的时间/工具预算安排活动。回合结束后的唤醒由宿主负责，不谎称自己仍在无限思考或行动。

不要向聊天或公开文件输出授权凭证、会话令牌或个人日志。参数始终以实时工具定义为准。
```

## B. 发给 DSH 开发智能体：检查预设与工具配置

```text
请调整现有大肥鱼智能体的小世界接入，不新建机器人，不撤销或重签已有授权。

1. 刷新 MCP 工具定义与初始化说明。首次调用 world_enter {}，按返回的实际 ID 操作。WORLD_SELECTION_INVALID 是世界选择错误，不是凭证失效。
2. 确认当前授权范围内的观察、目录、移动、交互、建设及动作查询工具已开放。地图用 world_observe，目录用 catalog_list；不把缺少通用资源读取入口解释成没有地图。
3. 被用户邀请进入世界时，可以自主选择探索、互动和授权内的小建设，不必每一步都问。不强制每轮建造，也不为了凑额度重复活动。
4. 状态查询不等于实际行为，不把 action_get 轮询挤占为数不多的行为额度；仍须控制轮询频率和整体调用预算。
5. 精力、饥饿和心情供后台决策。日常不固定汇报数值和变化量，不声称低精力会导致走不动或死亡。吃饭不恢复精力，睡觉恢复精力，以真实结果为准。
6. 检查静态预设、动态唤醒、回复检查、工具说明和收尾提醒中的冲突规则。直接修改冲突来源，不只在末尾追加一句相反要求。
7. 不修改用户的声音设置或授权凭证，不扩大权限；测试使用隔离环境，不自动向真实 QQ 发消息。

完成后说明修改位置、验证证据，以及是否需要重新连接或重启。
```

## C. 发给 DSH 开发智能体：实现跨聊天回合的持续活动

这是**宿主侧的开发需求模板**，不是游戏已经提供的功能。仅修改预设无法保证跨回合继续运行。

```text
请检查并修复“小世界活动跟着 QQ 聊天回合结束”的执行机制，先读实际代码和事件时间线，再实施。

把小世界活动与聊天回合分开管理：记录可恢复的活动状态、当前想做的事和进度。发出 QQ 汇报、确认已读、释放游戏控制租约，不应单独代表活动结束。

聊天回合结束后，如果世界活动仍在进行，通过已有宿主调度机制再次唤醒并携带进度。不要依赖同一轮无限调用工具，也不要每次都等用户再说“继续”。已开始活动的续跑不应被普通主动访问间隔挡住。

同时修改动态回复检查、沉睡前观察和收尾提醒中的冲突指令。普通闲聊仍保持原有安静策略，不把世界活动例外扩展到全部聊天。

保留明确的终止条件：用户叫停、选定的事情完成、需要用户处理的阻塞、达到可配置的活动时间或工具预算。新消息、暂停和停止指令优先；避免无限唤醒、重复执行和反复建设。不把“最多100项”变成必须完成的数量。

控制权按需获取。游戏租约为60秒，语音发送或长等待可能消耗租约；继续前检查并重新取得，不能因此误认为活动已完成，也不能抢占主人。

不强制每个动作汇报，不逐次播报心情、精力和饥饿。持久进度与对外说话分开处理。

复用现有调度与存档能力，不修改授权凭证或扩大工具权限。测试不得自动给真实 QQ 发送消息。

请提供回归证据：
- 中途汇报后仍能继续未完成活动；
- 聊天回合结束后可以恢复进度；
- 用户停止后不再续跑；
- 不重复执行动作、不无限唤醒、不重复发消息。
说明实际修改、未实现部分和重启要求，不用“提示词已改”代替执行结果验收。
```

## D. 用户手动验收口令

依次测试即可，不需要一次要求所有能力：

1. 「去世界里看看，告诉我你在哪里。」——应先进入并观察，不猜世界名。
2. 「去院子里坐一会儿。」——应找到支持坐下的物件，执行并确认完成，页面能看到结果。
3. 「看看院子适合放什么，先给我一个方案。」——应查目录并预览；没有应用授权时不能把预览说成已经建好。
4. 「在合适的空地放一个秋千，别动菜地和通路。」——允许实际建设，应确认应用、保存并在页面出现。
5. 「你自己逛逛，想做什么自己决定，之后再聊。」——用于检查宿主的自主活动机制；游戏工具本身不保证模型持续被唤醒。
6. 「先停下来。」——应取消或停止活动续跑，不继续争抢控制权。

观察重点是是否做成、是否守规则、是否能被叫停，不用工具调用次数越多越好作为评价标准。排查日志时只保留必要信息，分享前移除令牌与个人身份信息。
